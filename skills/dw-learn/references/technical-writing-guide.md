# Technical Writing Guide

Follow these rules for all technical writing:

1. **Use the `/simple-english` skill for all writing.** Keep language simple and easy to follow. Use short sentences, active voice, simple tenses, and unambiguous domain diction.
2. **Keep artifacts as terse as possible.** Short is better than long.
3. **Avoid walls of text.** Break content into short lists, tables, code blocks, or diagrams.
4. **Avoid inline file or class references and long historical inventories.** Put file lists, class references, or historical inventories in summary tables in an appendix at the end of the document only if needed.
5. **Prefer diagrams wherever possible.** Use Mermaid diagrams or draw.io (for complex diagrams) for system architecture, workflows, and processes. If a diagram gives a complete explanation, omit further prose.

## Mandatory Second Pass

Always take a second pass over any technical writing to check whether you can shorten or simplify it further. Cut every sentence, clause, or word that does not add a necessary fact or instruction.
